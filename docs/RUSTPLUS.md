# Rust+ — подключение, возможности, ограничения

## Что исследовано
- Rust+ Companion не имеет опубликованного Facepunch API для сторонних приложений; рабочий и широко используемый способ — тот же протокол, что у мобильного приложения: websocket-соединение с сервером (порт приложения) по `playerId` + `playerToken`, получаемым при сопряжении (push FCM после нажатия «Pair» в игре).
- Страница `facepunch.rust-plus-connect.com/companion/` запрещает автоматический доступ (robots) — не использовалась.
- Используется сообщественная MIT-библиотека **RustPlusApi** (HandyS11): пакеты `RustPlusApi.Fcm`, `RustPlusApi.Fcm.Registration` (NuGet) и клиент `RustPlusApi`, подключённый **исходниками** из `src/ThirdParty/RustPlusApi` (ветка `feat/companion-socket`, см. раздел ниже). По исходному коду библиотеки подтверждены `ConnectAsync`, `GetInfoAsync`, `GetTimeAsync`, `GetTeamInfoAsync`, `GetTeamChatAsync`, `SendTeamMessageAsync`, `GetSmartSwitchInfoAsync`, `GetAlarmInfoAsync`, `GetStorageMonitorInfoAsync`, `SetSmartSwitchValueAsync`, `SetSubscriptionAsync`; websocket-операции `getEntityInfo`, `setEntityValue`, `checkSubscription`, `setSubscription`.
- Проверены реальные FCM-события `OnEntityPairing`, `OnSmartSwitchPairing`, `OnSmartAlarmPairing`, `OnStorageMonitorPairing`, `OnServerPairing`, `OnAlarmTriggered`. Общее `OnEntityPairing` содержит `PlayerId`, `PlayerToken`, `ServerId` (GUID), `PersistentId` и `Data` с `EntityType`, `EntityId`, `EntityName`; специализированные события передают Entity ID в `Data`.
- **Точное ограничение протокола:** уведомление о сопряжении приходит после нажатия Pair в игре. В protobuf и API нет операций accept/reject для сопряжения устройства. Поэтому карточка не имитирует подтверждение: «Проверить и добавить» выполняет реальное `getEntityInfo`, а «Скрыть» лишь локально скрывает карточку.

## Архитектура
- `RustCompanion.Core.RustPlus` — модели, `IRustPlusGateway`, `RustPlusManager` (состояния, опрос, переподключение 2→5→10→20→30→60 с, остановка при недействительной авторизации; при HTTP 418 — пауза 5 мин), бот, устройства/тревоги, разбор push, репозитории. Без зависимости от библиотеки; покрыто тестами с поддельным шлюзом.
- `RustCompanion.RustPlus` — адаптер к библиотеке. **Все вызовы через отражение**, поэтому проект компилируется независимо от имён членов версии 2; при несовпадении сообщение об ошибке содержит список доступных методов библиотеки (его можно прислать для исправления).
- Токен игрока и учётные данные FCM хранятся только в DPAPI (`%LOCALAPPDATA%\RustCompanion\secrets`), не в БД, экспорте и логах; временный файл при сохранении/загрузке учётных данных затирается и удаляется.

## Как подключиться
1. Вкладка **Rust+** → «1. Войти через Steam»: откроется окно входа внутри приложения (WebView2, он есть в Windows 10/11); вход и Steam Guard подтверждаете вы. С октября 2026 Facepunch завершает вход редиректом на `rust-plus://rust-auth-session/?token=…&steamId=…`, а страница `/app` не делает редирект, если в User-Agent есть «Windows», — поэтому окно отправляет User-Agent не от Windows и перехватывает редирект. Окно закрывается само, временный профиль браузера удаляется.
2. «2. Ждать сопряжения в игре» → в Rust: Esc → Rust+ → «Pair with server» (сопряжение с текущим сервером).
3. Сервер появится в списке → «Подключиться». Состояние: Подключено / Подключение / Переподключение / Нужно повторное сопряжение / Отключено.
4. Устройства: в игре нажмите Pair на Smart Switch/Smart Alarm/Storage Monitor. FCM-событие создаст карточку на обеих вкладках. Нажмите «Проверить и добавить»: только после успешного чтения через Rust+ устройство сохраняется в SQLite и появляется в общем списке. Ручной ввод Entity ID удалён.

## Реализовано (код написан; не проверялось на реальном сервере — среда разработки не может запустить игру/Rust+)
- Сопряжение, хранение секретов, подключение, статус, переподключение, обработка устаревшей авторизации, корректное отключение.
- Информация о сервере (название, онлайн, очередь, размер карты), игровое время, команда (онлайн/жив/координаты, если отдаёт сервер).
- Командный чат (просмотр, отправка), история при подключении не считается новыми сообщениями, дедупликация.
- Умные устройства: автоматическое обнаружение по FCM, постоянные дедуплицированные карточки, проверка реальным чтением перед сохранением, строгая привязка по Rust+ Server ID/Player ID/адресу. Обе вкладки используют один репозиторий, менеджер и `RustPlusHub`. Ручного добавления нет.
- Smart Switch: включение/выключение только с подтверждающим чтением; квадрат зелёный при достоверно включённом, красный при достоверно выключенном, серый при неизвестном состоянии или недоступности. Smart Alarm: индивидуальный колокольчик, история и защита от дублей (10 с), без команд питания; его значение не трактуется как питание или режим охраны, индикатор остаётся серым. Storage Monitor: показ содержимого.
- Миграция SQLite v10 добавляет Rust+ Server ID, карточки сопряжения и метаданные последней достоверной синхронизации; старые серверы и устройства сохраняются.
- Бот: `!time`, `!pop`, `!timer`, префикс, язык (ru/en), включение каждой команды, проверка поддержки, расширяемость (`IBotCommand`). По умолчанию выключен.
- Уведомления: события «сработала сигнализация» и «потеря соединения» подключены к общей системе (оверлей/Windows; по умолчанию выключены).

## Не реализовано / ограничения
- Карта сервера (`GetMapAsync`, монументы, слои), показ устройств и команды на карте — следующий этап.
- Звуки тревог и Telegram для сигнализаций, повторное подключение FCM после сетевого сбоя (слушатель перезапускается только при запуске приложения).
- Уведомления об AFK, гибели участника и входе/выходе: отдельные события Rust+ не подключены.
- Лимит длины сообщения чата (128) — консервативное допущение. Определение «авторизация истекла» — эвристика по тексту ошибки.
- Игровое время для `!time` — как отдаёт Rust+; оценки реальных минут до заката не делаются.

## Известное ограничение: прямое подключение закрыто Facepunch (ноябрь 2026)

**Симптом.** На каждую попытку подключения два отказа: «Unable to connect to the remote server» (прямое подключение к порту Rust+) и «The server returned status code '418' when status code '101' was expected» (старый прокси Facepunch `wss://companion-rust.facepunch.com/game/{ip}/{port}`). Порт открыт, сопряжение и FCM работают. Подсказка «токен мог устареть» в таком случае неверна: сопряжение в порядке, закрыт сам канал.

**Что известно (источники сторонние, не документация Facepunch; код прочитан, проверено только по коду):**
- Facepunch убирает прямые подключения к `app.port`; старый маршрут `/game/{ip}/{port}` отвечает 418 для всех серверов. Об этом говорят коммит и документация ветки `feat/companion-socket` в https://github.com/HandyS11/RustPlusApi (файлы `docs/articles/rustplus-client.md`, `docs/articles/troubleshooting.md`, коммит `b0a3a78`) и PR #213 в https://github.com/Pronwan/rustplus-desktop (комментарий в `src/RustPlusDesktop/Services/RustPlusClientReal.cs`, `ConnectAsync`).
- Новый маршрут: `wss://companion-rust.facepunch.com/socket/{ServerId}` (`ServerId` — GUID из уведомления о сопряжении). Токен входа Facepunch (тот же, что возвращает вход через Steam, «companion login token») передаётся **двумя WebSocket-субпротоколами**: `rustplus.auth.v1`, затем base64url(UTF-8(токен)) без `=` (`src/RustPlusApi/RustPlusEndpoint.cs`, методы `GetUri` и `GetSubProtocols`, ветка `feat/companion-socket`, коммит ad43105). Дальше идёт обычный протокол Rust+ (protobuf `AppRequest`/`AppMessage`) c `playerId` + `playerToken`.
- Отказы: HTTP 403 при рукопожатии сокета — токен входа отклонён; HTTP 404 — неизвестный ID сервера; соединение открылось, но `getInfo` вернул `not_found` — неверный токен игрока (источники: документация ветки и `RustPlusClientReal.cs` в rustplus-desktop). Заметьте: для запросов к устройствам `not_found` означает «устройства нет», поэтому как «неверный токен игрока» он трактуется только на первом `getInfo`.
- Лента разработки Rust: слияние «rustplus_remove_direct» от 4 ноября 2026 (по данным постановки задачи; сам источник не проверялся).

**Что сделано в приложении.**
- Порядок попыток (`RustPlusLibGateway.ConnectAsync`, логика выбора и разбора ошибок — `Core/RustPlus/Routes.cs`): (1) новый канал, если известны ID сервера и токен входа; (2) прямое подключение как запасной путь. Старый прокси `/game/…` больше не пробуется — он всегда отвечает 418.
- Клиент `RustPlusApi` подключён исходниками из `src/ThirdParty/RustPlusApi` (MIT, коммит `ad4310583ee2c7c6a6dbd6b412df382ef92d461b`, файлы без правок; `THIRD_PARTY.md` рядом). В опубликованном пакете 2.0.0-beta.9 маршрута `/socket/` нет. Когда он выйдет в пакете NuGet, проект можно заменить на `PackageReference`.
- Токен входа Facepunch раньше нигде не сохранялся (в учётных данных FCM для него нет поля) — теперь сохраняется при входе через Steam в DPAPI (`rustplus_companion_token`), не в БД/экспорте/логах. ID сервера берётся из `PairedServer.RustPlusId` (миграция v10).
- Коды отказа (`RpErrors`): `facepunch_direct_removed` (HTTP 418; не ошибка авторизации, менеджер ждёт `RustPlusManager.DirectRemovedPause` = 5 мин и повторяет, сопряжение не сбрасывается), `companion_login_rejected` (403; требуется новый вход через Steam), `companion_server_unknown` (404; сопрячь сервер заново), `companion_not_ready` (не хватает токена входа и/или ID сервера; обычные короткие повторы, данные перечитываются на каждой попытке).
- Токены не пишутся в журнал и сообщения: `Redactor` маскирует зарегистрированный токен входа (и его base64url-форму) и параметры вида `…Token=`, `RpCredentials.ToString()` скрывает оба токена.

**Что НЕ подтверждено.** Реальное подключение через `/socket/{ServerId}` не проверялось (в среде разработки нет Windows, Rust+ и доступа к серверам). Как именно официальное приложение передаёт токен, известно только из кода сторонних клиентов; других шагов рукопожатия в них нет, но Facepunch может изменить протокол без предупреждения. Если после 403 вход через Steam не помогает — пришлите строки журнала `Rust+` (токены в них скрыты).

**Если ID сервера пуст** (сервер сопряжён до того, как приложение стало его сохранять): в игре снова нажмите Esc → Rust+ → «Pair with server» при запущенном приложении — уведомление обновит ID сервера и токен игрока.
