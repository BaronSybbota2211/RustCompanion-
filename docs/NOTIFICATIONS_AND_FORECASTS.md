# Уведомления, оверлей, прогнозы, гниение

## Уведомления
- Каталог событий: ручные таймеры (РТ, Deep Sea, вертолёт, Bradley), контейнер, прогнозы Чинука/вертолёта/аэрдропа, Bradley, гниение,
  события наблюдения за игроками (вход, выход, порог группы). Для каждого — независимые переключатели «Оверлей» и «Windows»
  (для событий игроков — ещё «Telegram/Discord»). Список в коде: `NotifyCatalog`; тест проверяет, что каждый идентификатор события есть в каталоге.
- По умолчанию всё выключено. Настройки хранятся в таблице `notification_prefs`; отсутствие записи = выключено, поэтому после обновления базы
  у существующих пользователей новые переключатели выключены, а таймеры и данные сохраняются.
  **Следствие:** ручные таймеры, которые раньше показывали уведомления автоматически, теперь молчат, пока вы не включите их в «Уведомлениях».
- Выключение отключает только показ: таймеры, прогнозы, история и расчёты продолжаются. Если уведомление выключено, «разовое» предупреждение не
  расходуется — включив его внутри окна предупреждения, вы его получите. Включённое предупреждение показывается один раз на событие/цикл/версию записи
  (ключ хранится в БД и переживает перезапуск).

## Оверлей
Собственное окно поверх остальных: не активируется (`WS_EX_NOACTIVATE`), пропускает мышь и клавиатуру (`WS_EX_TRANSPARENT`), не в Alt+Tab.
Угол, отступ, длительность и число плашек настраиваются. Повтор того же текста не создаёт дубликат.
- Работает поверх оконного и безрамочного режима Rust. **Поверх эксклюзивного полноэкранного режима не гарантируется** — переключите Rust в Windowed/Borderless.
- Проверить вживую можно кнопкой «Тестовая плашка» в «Уведомлениях». Автоматически проверена только логика флагов окна, размещения и очереди.
- Скрыть плашки: кнопка «Скрыть плашки» или пункт «Скрыть оверлей» в меню значка трея. Глобальная горячая клавиша не реализована.

## Прогноз Чинука / вертолёта / аэрдропа
Только по вашим нажатиям, отдельно для каждого сервера. Метод: медиана до 7 последних интервалов; случайные двойные нажатия (меньше 2 минут) игнорируются.
Диапазон — по разбросу (MAD); при большом разбросе уверенность «низкая», диапазон = от минимального до максимального недавнего интервала.
Погрешность ±30 минут и любые универсальные интервалы **не зашиты**. Если окно прогноза прошло — показывается «ожидаемое окно прошло», а не обратный отсчёт.
Предупреждение — за 10 минут до расчётного времени. Аэрдроп: прогноз только если интервалы регулярны (разброс ≤ 25% при ≥ 5 наблюдений), иначе «прогноз недоступен».
Минимумы наблюдений (4 и 5) и порог регулярности — решения реализации, а не игровые факты.

## Респавн РТ
Отдельный счётчик по нажатиям «РТ респавн» (см. `docs/MONUMENTS.md`): прогноз уже по двум нажатиям, с пометкой низкой уверенности, пока интервалов меньше трёх; предупреждение за 10 минут.

## Bradley
Универсальное время респавна **не подтверждено**: по найденным источникам оно зависит от сервера/плагинов (настраиваемые минимумы/максимумы в плагинах,
а в документации Facepunch есть только команда quickrespawn). Поэтому интервал или диапазон вы задаёте для каждого сервера. Без него фиксируется уничтожение,
но отсчёта нет. Отсчёт стартует только после «Bradley уничтожен»; кнопки «Bradley появился» нет. После расчётного времени показывается «расчётный интервал
завершился» без утверждения, что Bradley появился. Новое уничтожение начинает новый цикл. (Ручной таймер Bradley на отдельной вкладке сохранён без изменений.)

## Закрытый контейнер / событие
В исходном коде такого таймера не было (расхождение с описанием в задании) — добавлен как отдельный ручной таймер: 15 минут, предупреждение на 14-й минуте, по одному на таймер.

## Гниение (вместо Upkeep)
Старый калькулятор Upkeep удалён из интерфейса и кода (данные таблицы `base_profiles` в базе не трогаются).
Модель: урон от decay линеен → оставшееся время = полное время гниения материала × (HP / макс. HP) / множитель decay сервера.
Источники — сторонние справочники и калькуляторы (в основном совпадают: дерево 3 ч, камень 5 ч, металл 8 ч, МВК 12 ч; линейность; множитель `decay.scale`,
по Facepunch wiki равный 1 по умолчанию). **Исходный код игры и официальные формулы не проверялись**, поэтому значения — справочные и редактируются в
«Параметрах расчёта». Максимальный HP элемента не зашит (он зависит от типа элемента и материала) — его вводит пользователь вместе с текущим HP.
Без HP показывается только верхняя граница («не позже, чем») и просьба ввести данные; предупреждение за 5 минут для такой записи не создаётся.
Разброс ±10 минут — шаг начисления decay по справочникам (не подтверждён). Приложение не знает реального состояния объекта и сервера.
Особенности отдельных элементов (двери, проёмы и т. п.) и «защита» от decay не моделируются.

## Проверка вручную
1. Первый запуск → «Уведомления»: все переключатели выключены; создайте контейнер — предупреждения нет, таймер идёт.
2. Включите «Оверлей» для контейнера → «Контейнер активирован» → на 14-й минуте плашка; повторно не появляется.
3. «Чинук замечен» четыре раза на одном сервере → появляется прогноз; на втором сервере — «Недостаточно данных».
4. «Bradley уничтожен» без интервала → сообщение «интервал не задан»; задайте интервал → отсчёт; новое нажатие → новый цикл.
5. «Гниение»: добавьте 5 объектов — шестой отклоняется; без HP — только верхняя граница.
6. Rust в Borderless → «Тестовая плашка» видна поверх игры; в Exclusive Fullscreen — может быть не видна.
