# Руководство разработчика

## 1. Требования

- Windows 10/11 для запуска WPF-приложения.
- .NET 10 SDK.
- Git.
- Доступ к NuGet для восстановления зависимостей.

## 2. Структура решения

Откройте `RustCompanion.slnx`.

Проекты:
- `src/RustCompanion.App` — WPF-приложение;
- `src/RustCompanion.Core` — основная логика;
- `src/RustCompanion.RustPlus` — интеграция Rust+;
- `src/ThirdParty/RustPlusApi` — сторонний API-клиент;
- `tests/RustCompanion.Tests` — тесты.

## 3. Восстановление и сборка

Из корня репозитория:

```powershell
dotnet restore RustCompanion.slnx

dotnet build src/RustCompanion.App/RustCompanion.App.csproj -c Release
```

Запуск:

```powershell
dotnet run --project src/RustCompanion.App/RustCompanion.App.csproj
```

## 4. Тестирование

```powershell
dotnet test tests/RustCompanion.Tests/RustCompanion.Tests.csproj -c Release
```

Тесты Core могут выполняться отдельно от игрового сервера.
Проверка реального Rust+ соединения требует доступной инфраструктуры
и корректного сопряжения.

## 5. Публикация Windows x64

```powershell
dotnet publish src/RustCompanion.App/RustCompanion.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -o publish
```

## 6. Основные правила разработки

- Сохраняйте разделение UI и бизнес-логики.
- Не переносите сетевую или доменную логику в code-behind без необходимости.
- Используйте существующие сервисы и репозитории.
- Не храните секреты в исходниках, настройках по умолчанию и тестовых данных.
- Не записывайте токены и ключи в журналы.
- Для новой логики добавляйте автоматические тесты.
- Сохраняйте обратную совместимость SQLite-миграций.
- Проверяйте отмену сетевых операций и обработку тайм-аутов.
- Не представляйте неполные или недоступные данные как достоверные.

## 7. Работа с SQLite

Изменения схемы выполняются через механизм миграций проекта.
Перед изменением существующих таблиц изучите предыдущие миграции
и сценарии восстановления базы.

Не удаляйте исторические миграции и не меняйте их смысл задним числом:
пользовательские базы уже могли пройти эти версии.

## 8. Работа с Rust+

Протокол Rust+ и инфраструктура Facepunch могут меняться.
Проверяйте фактические ответы и состояния соединения.
Не имитируйте успешное подключение при ошибках авторизации или сети.

Подробности: [RUSTPLUS.md](RUSTPLUS.md).

## 9. Перед отправкой изменений

1. Проверьте `git diff`.
2. Выполните сборку.
3. Запустите тесты.
4. Убедитесь, что секреты и локальные данные не попали в коммит.
5. Обновите документацию, если изменилось поведение.
6. Создайте понятный commit message.

## 10. CI

В репозитории имеется workflow `.github/workflows/build.yml`.
Результат CI следует проверять на странице Actions GitHub.
Наличие workflow само по себе не означает, что конкретный запуск прошёл успешно.
