# Архитектура Rust Companion

## 1. Назначение

Rust Companion — настольное приложение для Windows, объединяющее
инструменты мониторинга серверов Rust, наблюдения за игроками,
учёта игровых событий, таймеров, уведомлений и управления
поддерживаемыми устройствами Rust+.

Приложение не читает память процесса Rust, не внедряет код в игру
и не предназначено для обхода Easy Anti-Cheat.

## 2. Технологический стек

- C# и .NET 10.
- WPF для графического интерфейса.
- CommunityToolkit.Mvvm для MVVM-инфраструктуры.
- Microsoft.Extensions.DependencyInjection для внедрения зависимостей.
- SQLite через Microsoft.Data.Sqlite.
- Serilog для файлового журналирования.
- xUnit для автоматических тестов.
- WebView2 для встроенного окна авторизации Steam.

## 3. Структура решения

### RustCompanion.App

Точка входа Windows-приложения и пользовательский интерфейс.

Основные обязанности:
- запуск и завершение приложения;
- регистрация сервисов и зависимостей;
- создание главного окна;
- связывание View и ViewModel;
- системный трей и оверлей;
- пользовательские настройки и уведомления.

### RustCompanion.Core

Основная логика приложения, не привязанная к WPF.

Основные области:
- `Data` — база данных и репозитории;
- `Forecast` — прогнозы событий и расчёты;
- `Hotkeys` — горячие клавиши;
- `Models` — модели данных и настроек;
- `Net` — сетевые источники и запросы;
- `Notifications` — маршрутизация уведомлений;
- `RustPlus` — состояние соединения и устройства;
- `Services` — общие сервисы и диагностика;
- `Watch` — мониторинг серверов и игроков.

### RustCompanion.RustPlus

Адаптационный слой для взаимодействия Core с библиотекой RustPlusApi.

### ThirdParty/RustPlusApi

Подключённая исходниками сторонняя реализация Rust+ API.
Её лицензия и сведения об авторстве находятся рядом с исходниками.

### RustCompanion.Tests

Автоматические тесты логики Core. Тесты используют xUnit.

## 4. Запуск приложения

При запуске `App.xaml.cs`:

1. Создаётся каталог локальных данных.
2. Настраивается файловое журналирование.
3. Инициализируется SQLite.
4. Создаётся контейнер внедрения зависимостей.
5. Регистрируются репозитории, сетевые клиенты и сервисы.
6. Создаётся главное окно приложения.

Сервисы регистрируются через Microsoft.Extensions.DependencyInjection.
Основные зависимости Core передаются через конструкторы.

## 5. Хранение данных

Основной каталог:

`%LOCALAPPDATA%\RustCompanion`

В нём размещаются:
- `companion.db` — локальная база SQLite;
- `logs` — журналы приложения;
- `secrets` — локально защищённые секреты.

Секреты защищаются Windows DPAPI. Не копируйте их в публичные
репозитории и не прикладывайте к диагностическим отчётам.

Перед ручным обслуживанием базы рекомендуется сделать резервную копию.

## 6. Сетевые взаимодействия

Приложение использует внешние источники для получения серверной
и игровой информации. Доступность данных зависит от источника,
сетевого соединения, ограничений серверов и пользовательской настройки.

Для Rust+ используется отдельный адаптер. Статус подключения
должен отражать фактический результат соединения, а не только
наличие сохранённых данных сопряжения.

## 7. Диагностика и журналы

Диагностические сообщения проходят через `DiagnosticsService`.
Перед записью выполняется очистка чувствительных данных
посредством Redactor.

Файловые журналы создаются в каталоге `logs`.
В конфигурации запуска предусмотрены ротация и ограничение
количества хранимых файлов.

Перед передачей журналов третьим лицам всё равно проверьте,
что в них нет персональных данных.

## 8. Границы достоверности

Необходимо различать:
- данные, полученные непосредственно от сервера;
- локально записанные наблюдения;
- вычисленные оценки и прогнозы;
- функции, зависящие от сторонних протоколов.

Прогнозы событий не гарантируют точное время появления.
Мониторинг игроков зависит от доступности и полноты ответов A2S/Steam.
Функции Rust+ зависят от протокола и инфраструктуры Facepunch.
